# Working in this repository

A ubCode / ubTrace demo project: a BMS whose requirements, architecture, software
requirements, code and tests are one traceable needs graph. [README.md](README.md)
is the full tour — this file is only the part an agent cannot infer from the
sources.

## Two spec files are GENERATED — never edit them by hand

| file | generated by | from |
| --- | --- | --- |
| `specs/_global/gaps.rst` | `tools/import_gaps.py` | `reports/gaps/gaps.json` |
| `specs/_global/test_results.rst` | `tools/import_test_results.py` | `reports/junit/testresults.xml` |

Both are committed on purpose — a fresh clone has to carry the full 194-need
graph, or `ubc check`, `ubc agent *` and the IDE are blind to the ~51 imported
needs until someone runs a script. So they are generated *and* in git, which
means they can go stale.

Refresh them after any change to `specs/`, `src/` or `tests/` — **all three
steps**, which is what the pre-commit hook and CI each do (`$UBC` is resolved
below):

```bash
snap="$(mktemp)"
"$UBC" agent gaps -p . > "$snap" || true    # exits 1 when it finds a gap — expected
python3 -c 'import json,sys; json.load(open(sys.argv[1]))' "$snap" \
  && mv "$snap" reports/gaps/gaps.json      # only once it parses
python3 tools/import_gaps.py                # -> specs/_global/gaps.rst
python3 tools/import_test_results.py        # -> specs/_global/test_results.rst
```

**Re-capture the snapshot, do not skip to the importers.** Closing a gap (a test
that satisfies a requirement) or opening one (a need with no parent) changes
`reports/gaps/gaps.json` without making either importer fail, so importing alone
re-derives `gaps.rst` from the old graph — describing the one place you just
changed incorrectly.

Never redirect `ubc agent gaps` straight into the committed file: the shell
truncates it before `ubc` writes a byte, so a failed run leaves an empty snapshot.

Both importers are standard-library-only, take no arguments, and are safe to
re-run: an unchanged input rewrites the same bytes. Run all three before
`ubc build needs` or `ubc agent gaps`, or the graph you reason about is missing the
current `gap` and `test_result` needs.

With no `ubc` available, run the two importers alone and say so — the snapshot
keeps what it had, and CI re-captures it. `import_gaps.py` exits 1 when the
snapshot names a need the sources no longer contain, which is the same staleness
seen from the other side.

You do **not** have to install or run the hook: it does this on a human's commit,
and the pipeline does it again and commits the result. Leaving these files stale is
recoverable; hand-editing them is not.

## The `ubc` CLI is not on PATH

It ships inside the ubCode VS Code extension, at a user- and version-specific
path. Resolve it, do not guess:

```bash
UBC="$(echo ~/.vscode/extensions/useblocks.ubcode-*/server/cli/ubc)"
"$UBC" check
```

A `ubc` from `PATH` is fine too. Prefer the newest extension build when several
are available, since CI installs the newest published version and an older engine
may regenerate the snapshots differently. If no binary exists at all, `ubc` is
unavailable here — report that rather than guessing.

## The workflow skills are generated too

Everything under `.claude/skills/`, `.agents/skills/`, `.github/agents/`,
`.claude/commands/` and `quality/*.toml` is installed by `ubc agent install`
from the `vmodel` profile and is listed with a SHA-256 baseline in
[.pharaoh/agent/install-manifest](.pharaoh/agent/install-manifest). The three
harness directories are three renderings of ONE profile, not three files to keep
in sync by hand.

Do not edit them. An edit drifts them from their recorded baseline and a later
`ubc agent install --overwrite`, or a bump past `profile_version 9`, discards it.
Project-specific guidance belongs in this file; the process wiring
(`[[workflow.stages]]`, `[quality.type_configs.*]`) belongs in
[ubproject.toml](ubproject.toml).

## Two tests fail on purpose

`uv run pytest -q` reports `2 failed, 48 passed`. That is the demo, not a
regression — see [README.md](README.md#two-tests-are-red-on-purpose). Do not
"fix" them.
